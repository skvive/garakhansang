## 서비스 아키텍처: 하나의 서버 원장, 세 가지 앱

```text
고객 앱 / PWA ───> [Neon Auth + 모바일 BFF] ───> 운영 상품/옵션/가격/재고
                                  │
                                  ├─ 견적→주문 초안→PG Checkout (Stripe/Toss)
                                  │                          │
                                  │             서명 검증 웹훅/금액 대사
                                  │                          ▼
                                  └───── 단일 주문 원장 + 이벤트 아웃박스
                                                 │
                              ┌──────────────────┴───────────────────┐
                        상인 콘솔/PWA                         배달기사 PWA
                        접수·거절·조리                         배차·픽업·배송
                              │                                   │
                              └──────── 관리자/운영 콘솔 ──────────┘
                                       주문 · 환불 · CS · 정산
```

**중요:** 고객 앱, 상인 앱, 라이더 앱은 서로 클라이언트에서 주문·결제 상태를 수정하지 않는다. 모두 한 서버에서 역할 권한·상태 전환·이벤트/푸시를 처리한다.

## 실제 고객 구매 흐름

1. 주소/서비스 권역 확인 (주소 저장 동의, 권역 검증; 불가능하면 주문 차단).
2. 운영서버 `GET /api/v1/mobile/products/{slug}`로 승인된 상품 상세/이미지/원산지/알레르기/옵션과 영업시간 표시.
3. 옵션 그룹별 단일/복수 선택, 필수 선택/최대 수량 검증, 합계 즉시 반영. 가격·재고는 서버가 산출한 값으로 재검증.
4. `POST /api/v1/mobile/cart/quote`: SKU/옵션/수량·매장·서비스지역으로 견적. 배달비·할인/세금/최종금액 누락 시 결제 버튼 비활성.
5. `POST /api/v1/mobile/orders`: Neon Auth 사용자/주소/가격스냅샷/상점별 주문 분리/멱등키를 DB 원자 트랜잭션으로 생성 (현재 미구현).
6. `POST /api/v1/mobile/payments/prepare`: 결제 페이지 생성, 클라이언트에 비밀키 없음. PG에서 돌아와도 **서버 검증 전 주문은 미결제**.
7. PG 서명 검증→원장 대사→지불 완료 이벤트→상점별 주문 생성/알림 아웃박스. 환불/취소는 정책·PG 확인 후 원자 처리.

## 상인 화면(고객 결제 후)

- 매장/영업시간/품절/메뉴옵션/프로모션, 오늘 주문 접수 대기, 수락/거절, 조리중, 픽업준비, 배달 요청.
- 상인 권한은 `merchant_id`별로 분리. 결제 확인 안 된 주문은 상인에게 접수 요청하지 않는다.
- 주문 접수 시 알림은 FCM + 앱 알림함/폴링 대체. 토큰 폐기·알림 재시도·미응답 타임아웃을 서버가 관리한다.

## 라이더 화면 / Google 지도

- Rider Auth/가입·심사·차량 종류·근무상태, 서비스권역 기반 배차 카드, 수락 전 공개 범위 최소화.
- 수락된 라이더만 픽업지/고객 배송지와 길찾기, ETA, 픽업/전달 증빙 표시.
- Google Maps SDK/Routes API는 API 키 제한·사용량/비용·위치 권한 동의·권한 분리 확인 후 연결. 위치는 업무 중 필요한 기간만 수집, 실시간 좌표 보존/열람 제한.
- 중복 수락 방지: 배차 단일 소유 제약 + DB 조건부 갱신/잠금 + 상태 버전.
- 라이더 미배정/미수락/취소/배달실패 시 운영자에게 재배차 경보.

## 관리자 대시보드

가락한상 기존 관리센터 UI 재사용 + 상품 옵션/사진 승인, 사업자·영업정보, 회원, 주문/결제·취소/환불, 픽업/배달, 라이더 심사/권역, 알림, 정산, PG 대사, 전체 감사 추적. 최고관리자·상인·라이더·CS 역할별 최소권한. 실제 개인정보와 주문서는 인증되지 않은 사용자에게 노출하지 않는다.
