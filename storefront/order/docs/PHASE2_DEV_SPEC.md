**2026-11-02 / 기준 저장소 `skvive/garakhansang` / 작업 브랜치 `chatgpt/garakhansang-order-20261102`**

## 제품 범위

한국 전통시장 입점 상인을 연결하는 브랜드 배달 앱. 가락시장/노량진수산시장/남대문시장/동대문시장/지역 명소시장 등 시장마다 물류와 상품 옵션을 독립 운영한다. 고객 앱·상인 콘솔·공동집하센터·배달기사 작업 화면·운영 관리의 주문 데이터가 하나의 상태 흐름을 따르도록 설계한다.

## 상호작용 계약

1. 고객은 시장별 상품을 한 장바구니에 담는다. `POST /order/api/v1/orders`는 서버가 아이템 가격, 변형 옵션, 재고, 쿠폰을 재계산한다.
2. 다른 시장의 상품들은 **같은 checkout ID 아래에서도 각각 다른 order ID**를 받는다. 합배송은 같은 시장 범위에서만 가능한 것으로 간주한다.
3. 주문 생성은 `Idempotency-Key`(8~128자) + 본문 해시로 중복을 감지한다. 같은 요청/같은 키 재시도는 동일 응답, 같은 키/다른 본문은 409.
4. 저장 시 재고를 차감한다. 재고 부족이면 전체 요청을 롤백한다. 현재 시연 DB는 한 대의 SQLite 프로세스용이다.
5. 모의 결제 완료 전에는 점포 수락 불가. 점포는 자기 주문을 수락 후 준비 완료로 변경한다.
6. 모든 점포가 준비되어야 집하센터에서 인수하고 기사 배차 작업을 생성할 수 있다.
7. 집하센터가 기사 배정, 기사가 픽업→배송완료 순서로 이동한다. 역행이나 중복 상태 변경은 거절한다.
8. 집하 전 취소는 재고를 돌려준다. 실제 PG 환불은 수행하지 않는다.
9. 쿠폰은 시장별 주문 1개에만 적용된다. 각 장바구니 전체 시장 합산으로 최소주문액을 충족하지 않는다. 현 단계 `welcome`은 데모 환경 전역 1회 정책이고 고객별 제한은 미구현.

## 배송·상품별 세부 규칙

- **가락시장:** 청과·정육·수산 다점포 집하. 온도 구역 분리와 출고 시간 동기화가 필수이며, 현재 DB는 `cold` 플래그만 기록한다.
- **노량진:** 활어/회, 손질 옵션·실중량 보정·냉장/냉동 포장 필요. 현재 `sliced` 3,000원 옵션만 데모이고 실중량 추가 결제는 허용하지 않는다.
- **남대문:** 식품 유통기한·알레르겐 표기, 상온/냉장 혼합 검증 및 상점 휴무일 필수.
- **동대문:** 면 원단 색상/폭/MOQ/견적/사업자 자격 관리 및 퀵배송. 현재 카테고리/수량 시연만 지원.
- **지역 전통시장:** 산지표시, 택배사 연동, 교환·반품 배송비, 냉장 포장 책임 주체 검증. 다른 시장과 실제 공동배송 금지.

## 상용 보안·결제 전환 게이트 (아직 미구현)

- Neon Auth 또는 동등한 신뢰 가능한 IdP의 서버 측 검증/JWT audience·issuer 검사, 사용자–시장–상인 소속 관계 점검, 고객 주문 소유권 검사.
- 운영자는 별도 관리자 계정+MFA. 상인·배달기사·집하센터 역할별 최소권한, 승인 로그 및 재검토.
- 멀티사이트 동시재고 `SELECT FOR UPDATE`, 재고 예약 TTL, 결제전/결제후 장애복구 및 부분 취소·환불 경로.
- PG 승인 이후에만 실제 카드·간편결제 연결, 3DS/승인·매입·환불 처리, 웹훅 서명·재생 방지·조회 대사.
- 개인정보 최소 수집, 배달 위치 정보 단기 보존, 사업자 정보 및 식품 표시 의무, 고객분쟁 처리/소비자 확인 절차.
- 바쁜 시간대/배차 실패/배송 온도 이탈/라이더 사고/오프라인 수거 대비 관제와 CS.
