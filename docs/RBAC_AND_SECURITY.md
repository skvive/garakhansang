# 운영자 권한 및 보안 운영 기준

운영상 반드시 추가할 통제: 역할별 점포 범위(멀티테넌트), 개인정보 마스킹, 최소권한 서비스 계정, 중요 작업 2인 승인, 실제 재고·금액 변동 경보, OAuth 토큰 암호화/폐기, 접근 기록 장기 보존 정책, 운영자 MFA 및 비상 계정 폐기.

## 이미 구현된 베타 방어
- 비밀번호 PBKDF2-SHA256/600,000회, 유니크 salt; 14자 이상.
- 세션 토큰은 브라우저 `HttpOnly` Cookie, DB에는 SHA-256 해시만 저장, SameSite=Strict, 8시간 만료.
- GET 외 변경 작업은 로그인 + 서버 역할 확인 + 같은 출처 확인 + CSRF 토큰 필요.
- 로그인 시도 IP 단위 5분 8회 제한(단일 프로세스 메모리 기반).
- 임의 SQL 테이블/컬럼명 사용 금지(서버 고정 허용목록), 동적 값은 prepared statement.
- 주문·재고·정산 SQLite 트랜잭션, 재고 음수/중복 생성 제한.
- 승인 전 글·레시피·상인 비공개. 공개 콘텐츠는 실체 확인 조건 검증.
- 서비스 워커는 API 및 관리자·계정·결제 URL을 캐시하지 않는다.

## 공개 배포 이전 필수 보완
- 프로덕션 OIDC/Neon Auth와 관리자 MFA 통합, 세션 갱신·로그아웃 전파·비상 관리자 처리.
- 개인정보 저장/마스킹·보존 기간·삭제 동의, API 키 비밀관리, 토큰 암호화.
- Redis 또는 DB 기반 분산 rate limit + IP/WAF, TLS와 HSTS, 서명된 Webhook 및 재시도.
- 관리자 2단계 승인(정산 지급, 환불, 수수료 변경), 생산자 사업자 인증 및 세금 증빙.
- SQLite 단일머신 대신 PostgreSQL 트랜잭션, 메시지 큐, 감시 및 재해복구 테스트.
- 감사 로그 유실/변조 검출, 개인정보 다운로드 감사·승인 정책.

## 현재 확인된 운영 사이트 위험
기존 `skvive/garak`에 LEXI 해외 패션몰용 표기/관세 코드가 남아 있었고 시세판에서 할인율/slug 기반 임의 등락률을 표시하던 부분이 확인됐다. v5 안전 패치는 해당 문제의 수정안이지만 **운영 서버에 반영되었다는 증거는 없다**. 원본 코드·운영 DB 수정을 진행하기 전에 해당 위험을 다시 확인해야 한다.
